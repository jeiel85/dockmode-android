# Acceptance Criteria

## 1. 기능 완료 기준

- 앱이 기존 기능을 유지한 상태로 빌드됩니다.
- 사용자는 최소 5개의 대기모드 프리셋 중 하나를 선택할 수 있습니다.
- 최소 3개 이상의 프리셋은 실제 화면 구성이 서로 명확히 달라야 합니다.
- 선택한 프리셋은 앱 재시작 후에도 유지됩니다.
- StandbyActivity에서 선택한 프리셋이 적용됩니다.
- DreamService가 이미 구현되어 있다면 DreamService에서도 동일 렌더러를 재사용합니다.
- 캘린더 권한이 없어도 Calendar Board가 깨지지 않습니다.
- 사진 권한 없이도 Photo Frame Placeholder가 깨지지 않습니다.

## 2. 디자인 완료 기준

- Minimal Clock, Warm Bedside, OLED Night Clock은 반드시 서로 다른 분위기를 가져야 합니다.
- OLED Night Clock은 완전 검정 배경 또는 그에 가까운 저휘도 배경을 사용합니다.
- Warm Bedside는 야간 사용을 고려해 낮은 대비와 따뜻한 색감을 사용합니다.
- Battery Dock은 충전 상태를 시각적으로 표현합니다.
- Split Dashboard는 단순 중앙 시계가 아니라 2영역 이상의 정보 구성을 가져야 합니다.

## 3. 안정성 기준

- 권한이 없어도 앱이 crash 되지 않습니다.
- 배터리 퍼센트 정보를 얻지 못해도 앱이 crash 되지 않습니다.
- 기존 설정 데이터가 있으면 유지됩니다.
- 신규 DataStore 키 추가 시 기본값이 안전해야 합니다.
- DreamService가 없는 프로젝트라면 관련 변경을 강제로 추가하지 않고 후속 작업으로 기록할 수 있습니다.

## 4. 범위 준수 기준

- 네트워크 권한을 추가하지 않습니다.
- 외부 API를 추가하지 않습니다.
- 사진 권한을 추가하지 않습니다.
- 광고/분석/로그인 SDK를 추가하지 않습니다.
- 앱 ID와 namespace를 변경하지 않습니다.
- 기존 구현을 삭제 후 재작성하지 않습니다.

## 5. 검증 기준

최소 하나 이상의 검증 명령을 실제로 실행해야 합니다. 실행하지 못한 경우에는 환경 사유를 명확히 보고해야 합니다.

권장 검증:

```bash
./gradlew test
./gradlew lint
./gradlew assembleDebug
```

검증 성공으로 기록하려면 실제로 실행한 명령과 결과가 있어야 합니다.
