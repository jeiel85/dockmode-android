# Decision Log — Standby Preset Extension

## 2026-05-25 — 코드 기반 디자인 프리셋 우선

### 결정

대기모드 디자인 확장은 별도 디자인 소스나 이미지 에셋 없이 Jetpack Compose 코드 기반으로 우선 구현한다.

### 이유

- 현재 필요한 것은 초기 앱 재구현이 아니라 기존 앱의 대기 화면 다양화이다.
- 시계, 달력, 충전 상태, 카드형 레이아웃, 그라데이션, 야간 모드는 Compose 코드만으로 충분히 구현 가능하다.
- 이미지/사진/특수 폰트/외부 디자인 에셋은 이후 완성도 향상 단계에서 추가하는 것이 안전하다.
- 권한과 외부 의존성을 늘리지 않아 Play Store 정책, 개인정보, 유지보수 부담을 줄일 수 있다.

### 영향

- 1차 개발에서는 Photo Frame을 실제 사진 접근 기능이 아니라 placeholder로 구현한다.
- Weather는 이번 패치에서 제외한다.
- 레트로/픽셀/닉시관 같은 특수 스타일은 2차 디자인 확장으로 분리한다.

## 2026-05-25 — Preset 중심 구조 채택

### 결정

Mode/Theme/Widget을 내부 구조로 두되, 사용자는 Preset 단위로 선택하게 한다.

### 이유

- 사용자가 복잡한 조합을 직접 만들지 않아도 된다.
- 개발자는 새 디자인을 Preset 추가 방식으로 확장할 수 있다.
- 기존 StandbyActivity와 DreamService에서 같은 renderer를 공유하기 쉽다.

### 영향

- `StandbyPresetRegistry`와 `StandbyThemeRegistry`를 추가한다.
- 설정 저장은 `selected_standby_preset_id`, `selected_standby_theme_id` 수준으로 시작한다.
- 사용자 커스텀 테마 편집기는 이번 범위에서 제외한다.

## 2026-05-25 — 추가 개발 패치 범위 제한

### 결정

이번 묶음은 초기 구현 계획서가 아니라, 이미 개발된 앱에 적용하는 추가 개발 계획서로 관리한다.

### 이유

- 초기 개발이 완료된 상태에서 전체 설계서를 다시 적용하면 기존 구현을 망가뜨릴 수 있다.
- 에이전트가 앱을 새로 만들거나 대규모 리팩터링하는 것을 방지해야 한다.

### 영향

- `PATCH_SCOPE.md`를 추가했다.
- `AGENT_PROMPT.md`에 기존 구현 확인과 범위 제한을 명시했다.
