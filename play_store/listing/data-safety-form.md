# Play Console 데이터 보안 양식 (Data Safety) 답변 초안

Play Console > 정책 > 앱 콘텐츠 > 데이터 보안 양식에 입력할 답변입니다. v0.1 구현 기준이며, 향후 네트워크/계정 기능을 추가할 경우 반드시 함께 갱신해야 합니다.

## 1. 데이터 수집

| 질문 | 답변 |
|---|---|
| 앱이 사용자 데이터를 수집 또는 공유합니까? | **아니요 (No)** |

### 근거

- v0.1 범위에서 캘린더 이벤트는 화면 표시 목적으로만 메모리에 유지되며 별도 DB나 외부 서버에 저장·전송되지 않습니다 (PRIVACY.md §3).
- 네트워크 권한을 추가하지 않았으며 외부 호출 라이브러리(Retrofit, OkHttp, Firebase 등)를 포함하지 않습니다.
- 광고/분석/crash reporting SDK가 포함되지 않습니다.

## 2. 데이터 처리 관행

| 질문 | 답변 |
|---|---|
| 전송 중인 데이터가 암호화되어 있습니까? | 해당 없음 (외부 전송 없음) |
| 사용자가 데이터 삭제를 요청할 수 있습니까? | 해당 없음 (외부 저장 없음) |
| 독립적인 보안 검토를 받았습니까? | 아니요 |
| Play Families 정책을 준수합니까? | 해당 없음 (어린이 대상 아님) |

## 3. 권한 사용 이유 명시 (참고)

`READ_CALENDAR` 권한이 데이터 수집 항목으로 잘못 분류되지 않도록, 권한 사용 흐름을 함께 명시합니다.

- 권한 요청 시점: 사용자가 "캘린더 연동하기" 버튼을 명시적으로 누를 때
- 사용 범위: Android Calendar Provider의 오늘/예정 이벤트의 ID·제목·시작/종료 시간·종일 여부만 조회
- 사용 목적: 대기 화면(StandbyScreen / DreamService)에 일정 정보 표시
- 저장/공유: 메모리 외 저장 없음, 외부 전송 없음
- 거부 시 동작: 시계·날짜·충전 상태 기능은 정상 작동

## 4. 갱신 트리거

이 양식은 다음 변경이 발생하면 반드시 같은 PR에서 함께 갱신합니다.

- 네트워크 권한 추가 (`INTERNET`, `ACCESS_NETWORK_STATE` 등)
- Firebase, GA, Crashlytics, Sentry, 광고 SDK 추가
- 사용자 계정/로그인/결제 기능 추가
- 캘린더 외 권한 추가 (위치, 미디어, 마이크, 전화번호 등)
- 캘린더 이벤트를 로컬 DB나 파일에 저장하는 동작 추가
